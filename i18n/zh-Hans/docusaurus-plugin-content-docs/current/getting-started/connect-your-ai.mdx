使用 **mFT Trader API MCP**，在你常用的 AI 工具内查询账户、获取买卖报价及分析已完成 K 线，不需要编写交易程序。

:::info[接入前]
本指南使用 **Windows 及本地 MCP（stdio）**，默认停用交易。AI 工具会启动 adapter 并提供模型；你不需要额外的模型 API key，也不需要另开 server terminal。提供 **Codex、Claude Code、Cursor、Claude Desktop、OpenClaw 及 Hermes** 的设置指南。设置步骤不代表已认证该工具；已测试的流程请参阅[各工具验证状态](https://github.com/mF-Technologies/trader-api-mcp/blob/main/docs/host-acceptance.md)。
:::

## 1. 获取账户设置

登录 Trading Terminal，打开 **API Key Management**。创建具有 **Read** 权限的 API key，并复制账户的连接设置。请先使用已确认的 demo 账户。

这些资料只填入本地账户文件，**不要粘贴到 AI 对话**。设置程序会显示填写位置。你不需要自行交换 token 或编写 Python 登录程序。

<details>
<summary>需要哪些资料？</summary>

| 本地账户字段 | API Key Management 提供的资料 |
| --- | --- |
| `TRADER_API_KEY` | 生成的 API key，不是交换后的短期 token |
| `TRADER_API_USERNAME` | `username` |
| `TRADER_API_TRADE_KEY` | `trade_key`，按原值填写 |
| `TRADER_API_WEB_PROXY_URL` | WebProxy REST（`webproxy_endpoint`） |
| `TRADER_API_FXSERVER_REST_URL` | FxServer REST |
| `TRADER_API_FXSERVER_WS_URL` | FxServer WebSocket（`endpoint`） |
| `TRADER_API_PRICE_AGENT_WS_URL` | Price Agent WebSocket（`price_agent_endpoint`） |
| `TRADER_API_CHART_SERVER_URL` | ChartServer REST，不是 WebSocket |

同时参考连接设置及 Python 配置片段：片段不一定包含所有 REST URLs。保留系统提供的 base paths，并全程使用同一账户及环境。`demo` 标签不会将真实账户变成 demo 账户。

</details>

## 2. 运行引导设置

先[安装 uv](https://docs.astral.sh/uv/getting-started/installation/)，再打开新的 PowerShell terminal。uv 会管理 Python 及依赖包，不需要 Git 或自行创建虚拟环境。

:::info[安装候选版本]
目前 MCP 包以 wheel 提供，尚未在 package index 发布。按[包安装说明](https://github.com/mF-Technologies/trader-api-mcp/blob/main/docs/package-installation.md)获取 wheel 及对应 SHA-256，以 `Get-FileHash` 比对；不相符便停止。暂时不要只用包名安装。
:::

在已核对 wheel 的文件夹运行：

```powershell
uvx --no-config --no-env-file --managed-python --python 3.12 `
  --index https://mf-technologies.github.io/Python-package-repositories/simple/ `
  --default-index https://pypi.org/simple `
  --from .\mft_trader_api_mcp-0.1.0-py3-none-any.whl trader-api-mcp-setup
```

设置程序会创建账户文件（通常是 `%USERPROFILE%\.mft-trader-api\.env`）并暂停。填入 API Key Management 的资料、保存，再按 Enter；然后选择你的 AI 工具。程序会检查账户连接并输出**只读 MCP 设置**，不会修改 AI 工具的配置文件。

将 wheel 保留在固定文件夹，不要放在 uv 缓存内。完整保留输出的 `command`、`args` 及超时设置，AI 工具会按这些路径自动启动 MCP。

## 3. 配置客户端

选择刚才设置时所选的工具。只合并输出的 `mft-trader-api` 项目，保留其他 servers，再重新启动或加载工具。

**只读设置。** 启用交易前，请查看[所选工具的流程验证状态](https://github.com/mF-Technologies/trader-api-mcp/blob/main/docs/host-acceptance.md)。

<Tabs className="mcpHostTabs" groupId="trader-mcp-host">
<TabItem value="codex" label="Codex" attributes={{className: 'mcpHostCodex'}} default>

设置时选 **`codex`**。

1. 打开 `%USERPROFILE%\.codex\config.toml`。
2. 加入输出的 `[mcp_servers.mft-trader-api]` 区块；已存在便只替换该区块，保留其他设置。
3. 重新启动 Codex，检查 MCP tools；CLI 用户也可运行 `codex mcp list`。在新对话问下方的账户问题。

</TabItem>
<TabItem value="claude-code" label="Claude Code" attributes={{className: 'mcpHostClaudeCode'}}>

设置时选 **`claude-code`**。

1. 打开使用 Claude Code 的文件夹内的 `.mcp.json`。
2. 新文件可粘贴完整 JSON；已有设置便只将 `mft-trader-api` 合并至现有 `mcpServers`，保留正确的 JSON 逗号。
3. 在该文件夹重新启动 Claude Code，按提示允许加载 server，并以 `/mcp` 检查。

</TabItem>
<TabItem value="cursor" label="Cursor" attributes={{className: 'mcpHostCursor'}}>

设置时选 **`cursor`**。

1. 打开用户设置 `%USERPROFILE%\.cursor\mcp.json`，或当前工作区的 `.cursor/mcp.json`，选其中一种范围。
2. 在 `mcpServers` 内加入或替换输出的 `mft-trader-api` 项目。
3. 重新加载 Cursor，如有需要在 MCP 设置启用 server；在 Agent 对话问第一个问题。

</TabItem>
<TabItem value="claude-desktop" label="Claude Desktop" attributes={{className: 'mcpHostClaudeDesktop'}}>

设置时选 **`claude-desktop`**。

1. 打开 **Settings → Developer → Edit Config**。
2. 空白文件可粘贴完整 JSON；已有设置便只将 `mft-trader-api` 合并至现有 `mcpServers`。
3. 保存后完全退出 Claude Desktop，再重新打开。

</TabItem>
<TabItem value="openclaw" label="OpenClaw" attributes={{className: 'mcpHostOpenClaw'}}>

设置时选 **`openclaw`**。**仅限只读；实际工具内的流程尚未验证。**

1. 使用支持原生 outbound MCP（`mcp.servers`）的版本。
2. 将 `mcp.servers.mft-trader-api` 合并至使用中的 profile 的 `openclaw.json`，或使用已运行 Gateway 的 **Settings → MCP** 编辑器。
3. 重新加载所属运行环境，再问账户问题。uvx、wheel 及账户文件路径必须存在于该机器，而非只存在于显示对话的设备。

运行环境及工具权限检查请参阅 [OpenClaw 接入步骤](https://github.com/mF-Technologies/trader-api-mcp/blob/main/docs/agent-hosts.md#openclaw)。不要为测试连接而停止共享 Gateway。

</TabItem>
<TabItem value="hermes" label="Hermes" attributes={{className: 'mcpHostHermes'}}>

设置时选 **`hermes`**。**仅限只读；实际工具内的流程尚未验证。**

1. 打开使用中的 Hermes Agent（Nous Research）profile 的 `config.yaml`，通常位于 `~/.hermes/config.yaml`。
2. 将输出的 `mcp_servers.mft-trader-api` 合并至现有配置。保留 `trust: untrusted` 及其他 profile 设置。
3. 启动 `hermes chat`，或在支持的对话界面运行 `/reload-mcp`。路径必须存在于运行 Hermes 的机器。

详见 [Hermes 接入步骤](https://github.com/mF-Technologies/trader-api-mcp/blob/main/docs/agent-hosts.md#hermes-agent-nous-research)。

</TabItem>
</Tabs>

其他**本地 stdio** client 可在设置时选 `stdio`，使用输出的 `command` 及 `args`。这不是供 ChatGPT 或纯网页 AI 工具使用的 remote connector URL。支持配置格式，不代表已验证该工具的交易批准界面。

## 4. 问第一个问题

<CodeBlock className="mcpPrompt" language="text">{'显示我的账户余额、持仓及挂单，不要下单。'}</CodeBlock>

成功时应通过 MCP tools 返回账户资料，而非一般回答或只有“已连接”状态。然后问：

<CodeBlock className="mcpPrompt" language="text">{'列出我的账户可用的确切 API contract codes。'}</CodeBlock>

从结果选择 code，再问（替换占位值）：

<CodeBlock className="mcpPrompt" language="text">{'显示 <YOUR_API_CODE> 的最新 bid／ask，并说明报价是否新鲜。不要下单。'}</CodeBlock>

API code 可能与 terminal 显示名称不同。数据过时或不可用时必须如实说明。收市时没有新鲜报价，不能单凭这点判定账户连接成功或失败。

## 下一步

- **分析市场：** 要求计算确切合约的已完成 K 线 RSI(14)、SMA(20) 或 EMA(20)，并说明数据质量。另有本地 K 线查看器，但不是 terminal 图表控制或手机图表。
- **准备 demo 交易：** 先验证所选工具的批准流程，再按 [Demo trading](https://github.com/mF-Technologies/trader-api-mcp/blob/main/docs/demo-trading.md)另行启用；需要 Read + Trade 权限。OpenClaw／Hermes 维持只读。
- **获取帮助：** 参阅[设置故障排查](https://github.com/mF-Technologies/trader-api-mcp/blob/main/SUPPORT.md#setup-troubleshooting)、[工具验证状态](https://github.com/mF-Technologies/trader-api-mcp/blob/main/docs/host-acceptance.md)及[工具目录](https://github.com/mF-Technologies/trader-api-mcp/blob/main/docs/tool-catalog.md)。

:::warning[启用交易前]
每项操作都需要独立人工表单，显示已保存的账户、合约、数量及条款。一般 Allow 提示或对话回复不等于交易批准。结果为 `UNKNOWN` 时，保留 journal 并查询原 intent，不要再次提交。本指南不会启用无人监督或真实账户交易。
:::
